Below are ready-to-run psql commands (interactive or one-liners) to create the database/user if missing, grant the schema privileges required for tests, and set default privileges for future objects.

Notes:

Run these as the Postgres superuser (e.g., connect with psql -U postgres).
Replace passwords or names if your environment uses different values.
The DO blocks make the create steps idempotent (safe to re-run).
Interactive (recommended)
Open psql as the postgres superuser:
psql -U postgres -h localhost -p 5432

Then run the following SQL (paste all at once):

-- Create database if it doesn't exist
DO

$$ BEGIN IF NOT EXISTS (SELECT 1 FROM pg_database WHERE datname = 'contacts_dev') THEN PERFORM dblink_exec('dbname=postgres', 'CREATE DATABASE contacts_dev'); END IF; END $$; -- Create role/user if it doesn't exist; set/update password DO $$

BEGIN
IF NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = 'contacts_dev_user') THEN
CREATE ROLE contacts_dev_user WITH LOGIN PASSWORD 'contacts_dev_password';
ELSE
ALTER ROLE contacts_dev_user WITH PASSWORD 'contacts_dev_password';
END IF;
END
$$;

-- Allow connection and basic privileges on the database
GRANT CONNECT ON DATABASE contacts_dev TO contacts_dev_user;

-- Switch to the new database
\c contacts_dev

-- Grant USAGE and CREATE on the public schema so the user can create objects
GRANT USAGE ON SCHEMA public TO contacts_dev_user;
GRANT CREATE ON SCHEMA public TO contacts_dev_user;

-- If tables already exist and you want this user to access them:
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO contacts_dev_user;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO contacts_dev_user;

-- Ensure future objects created in schema public grant appropriate privileges automatically
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO contacts_dev_user;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT USAGE, SELECT ON SEQUENCES TO contacts_dev_user;

One-line (non-interactive) examples
Create DB (if missing) and user, then grant privileges (run from a shell as the postgres user):
psql -U postgres -h localhost -p 5432 -v ON_ERROR_STOP=1 -c "DO $$ BEGIN IF NOT EXISTS (SELECT 1 FROM pg_database WHERE datname='contacts_dev') THEN CREATE DATABASE contacts_dev; END IF; END $$;"

psql -U postgres -h localhost -p 5432 -v ON_ERROR_STOP=1 -c "DO $$ BEGIN IF NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname='contacts_dev_user') THEN CREATE ROLE contacts_dev_user WITH LOGIN PASSWORD 'contacts_dev_password'; ELSE ALTER ROLE contacts_dev_user WITH PASSWORD 'contacts_dev_password'; END IF; END $$;"

psql -U postgres -h localhost -p 5432 -d contacts_dev -v ON_ERROR_STOP=1 -c "GRANT USAGE ON SCHEMA public TO contacts_dev_user; GRANT CREATE ON SCHEMA public TO contacts_dev_user; GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO contacts_dev_user; GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO contacts_dev_user; ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO contacts_dev_user; ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT USAGE, SELECT ON SEQUENCES TO contacts_dev_user;"

Verify access (as the application/test user)
Quick check that the user can connect and run a simple query:
psql -U contacts_dev_user -h localhost -p 5432 -d contacts_dev -c "SELECT current_user, version();"

If this returns without error, the user can connect. Next, run the tests (from the repository):

mvn -DDB_USER=contacts_dev_user -DDB_PASS=contacts_dev_password -DDB_NAME=contacts_dev test

Optional: If you prefer the database to be owned by the user (so migrations can run without extra grants), as superuser run:
ALTER DATABASE contacts_dev OWNER TO contacts_dev_user;

Caveats & recommendations

Granting CREATE on schema public gives the user ability to create/drop tables in that schema — appropriate for test environments but not for production. For CI, using an ephemeral database or H2 in-memory is safer.
If you manage Postgres via Docker for tests, consider starting a container where the DB and user are created automatically (many CI setups do this).

Grant CONNECT on DB (optional if you used the DO block above, but safe):
psql -U postgres -h localhost -p 5432 -v ON_ERROR_STOP=1 -c "GRANT CONNECT ON DATABASE contacts_dev TO contacts_dev_user;"

Grant schema privileges and allow creating objects in public schema:
psql -U postgres -h localhost -p 5432 -d contacts_dev -v ON_ERROR_STOP=1 -c "GRANT USAGE ON SCHEMA public TO contacts_dev_user;"
psql -U postgres -h localhost -p 5432 -d contacts_dev -v ON_ERROR_STOP=1 -c "GRANT CREATE ON SCHEMA public TO contacts_dev_user;"

Grant privileges on existing tables and sequences (if any objects already exist):
psql -U postgres -h localhost -p 5432 -d contacts_dev -v ON_ERROR_STOP=1 -c "GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO contacts_dev_user;"
psql -U postgres -h localhost -p 5432 -d contacts_dev -v ON_ERROR_STOP=1 -c "GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO contacts_dev_user;"

Set default privileges so future tables/sequences are usable by the role:
psql -U postgres -h localhost -p 5432 -d contacts_dev -v ON_ERROR_STOP=1 -c "ALTER DEFAULT PRIVILEGES FOR ROLE postgres IN SCHEMA public GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO contacts_dev_user;"
psql -U postgres -h localhost -p 5432 -d contacts_dev -v ON_ERROR_STOP=1 -c "ALTER DEFAULT PRIVILEGES FOR ROLE postgres IN SCHEMA public GRANT USAGE, SELECT ON SEQUENCES TO contacts_dev_user;"

Notes and alternatives:

If your DB owner is not postgres (e.g., you created the DB as contacts_dev_user previously), change the FOR ROLE clause in ALTER DEFAULT PRIVILEGES to the role that creates objects (or run ALTER DEFAULT PRIVILEGES as that role).
If you prefer to run the few commands interactively inside psql, omit the -c and run them one by one in a psql session.
If you want a single script file, save the above commands to create_db_and_grants.sql and run: psql -U postgres -f create_db_and_grants.sql
